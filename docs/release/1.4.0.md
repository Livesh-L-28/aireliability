## 1. Overview

`aireliability` v1.4.0 is a major milestone release delivering an enterprise-ready, provider-agnostic reliability, evaluation, and regression-testing platform for Large Language Models (LLMs) and autonomous AI agent systems. 

This release introduces complete production systems for **AI Safety Validation** (Phase 41), **Reliability Prediction** (Phase 42), **System-Wide Observability Dashboard** (Phase 43), **Declarative Policy Governance** (Phase 44), **Enterprise Multi-Tenancy & RBAC** (Phase 45), and a full **REST API & Typed SDK Platform** (Phase 46).

## 2. Major Capabilities

### AI Safety Validation (`aireliability.safety`)
- **Sandboxed Campaign Runner**: Automated multi-category adversarial testing across prompt injections, instruction boundary overrides, unsafe tool executions, memory manipulation, and multi-agent coordination violations.
- **Deterministic Mutation Engine**: Mutates safety probes with homoglyphs, zero-width characters, token splitting, Base64/rot13/URL encodings, and framing prefixes.
- **Hard Safety Vetoes**: Non-compensatory safety scoring immediately caps composite reliability scores at $\le 0.30$ upon detecting critical security or safety breaches.

### Reliability Prediction (`aireliability.prediction`)
- **Forecasting Models**: Statistical time-series regression, exponential smoothing, volatility modeling, and Weibull hazard estimation for time-to-failure analysis.
- **Predictive Horizons**: Multi-horizon evaluations covering `NEXT_EXECUTION`, `SHORT_TERM`, `MEDIUM_TERM`, and `LONG_TERM`.
- **Feature Extraction**: 19 predictive signals spanning error patterns, agent trajectory deviations, RAG grounding drifts, and latency variance.

### Unified Intelligence Dashboard (`aireliability.dashboard`)
- **Cross-Subsystem Aggregation**: Combines telemetry and reliability metrics from Phases 1 through 46 into 21 specialized panels.
- **Multi-Format Serialization**: Exportable to structured JSON, human-readable Markdown summaries, and tabular CSV with SHA-256 state snapshot fingerprints.

### Reliability Policy Engine (`aireliability.policy`)
- **Precedence Hierarchy**: Strict evaluation precedence: `SECURITY > SAFETY > TENANT_ISOLATION > AUTHORIZATION > COMPLIANCE > RELIABILITY > PERFORMANCE > COST`.
- **Declarative Rule Engine**: Rich condition operators (`EQ`, `NEQ`, `LT`, `LTE`, `GT`, `GTE`, `IN`, `CONTAINS`, `REGEX_MATCH`) with explanation trees and rollback capabilities.

### Enterprise Multi-Tenancy (`aireliability.tenancy`)
- **Asynchronous Context Isolation**: Safe tenant scoping utilizing Python `contextvars`.
- **Granular RBAC**: Role-Based Access Control supporting `ADMIN`, `OPERATOR`, `DEVELOPER`, `AUDITOR`, and `VIEWER` roles.
- **Usage & Quotas**: Real-time quota enforcement across concurrent jobs, token consumption, and API request rates.

### REST API & Typed SDK Platform (`aireliability.api` & `aireliability.sdk`)
- **FastAPI Control Plane**: 24 REST endpoints covering evaluations, predictions, dashboards, policies, tenants, async background tasks, and webhooks with HMAC-SHA256 signature verification.
- **Typed Python SDK**: High-performance synchronous `Client` and asynchronous `AsyncClient` supporting context managers, streaming, and structured exception hierarchies.

## 7. Quick Start

### 1. Basic Evaluation & Testing

```python
from aireliability.core.models import TestCase
from aireliability.evaluation.engine import EvaluationEngine

engine = EvaluationEngine()
test_case = TestCase(
    id="eval_001",
    name="Greeting Test",
    input={"prompt": "Hello!"},
    expected_output={"response": "Hello! How can I assist you today?"},
)

result = engine.evaluate(
    test_case=test_case,
    actual_output="Hello! How can I assist you today?",
)
print("Evaluation Status:", result.status)
```

### 2. Python SDK Client

```python
from aireliability.sdk import Client

with Client(base_url="http://localhost:8000", api_key="airel_dev_key") as client:
    health = client.dashboard.get_health()
    print("Platform Health:", health["health_status"])
```

### 3. Command Line Interface

```bash
# Print installed version
airel --version

# Run safety campaign
airel safety --help

# Inspect multi-tenant quotas
airel tenant --help
```

## 10. Known Limitations

- **In-Memory Default Backends**: Built-in state stores, knowledge graphs, and queues operate in-memory by default. For horizontally distributed production deployments with multiple nodes, use the optional PostgreSQL (`aireliability[postgres]`) and Redis (`aireliability[redis]`) persistence adapters.
- **Language Models**: Built-in deterministic LLM adapters provide offline testing and fixture replay; production evaluation against remote LLM providers requires user-configured provider keys or local inference engines (Ollama, vLLM).
